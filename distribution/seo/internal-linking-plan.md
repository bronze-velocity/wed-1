# Internal Linking Plan — `/apps/[slug]`

*Generated 2026-08-24. Related-app rankings computed from `zz/wed-apps/20-apps.json` using a weighted overlap score: `2×|shared vibes| + 2×|shared moments| + 1×|shared feelings|`. Non-app-page targets pulled from live routes + the proposed blog pages in `distribution/seo/keyword-to-page-map.md`.*

## Rules

- **Where the links go:** every `/apps/[slug]` page renders a "You might also want…" block near the bottom (before the CTA), plus 2 non-app contextual links inside the body (one in the intro/scene section, one in the objections/FAQ section).
- **How many:** 4 related apps + 2 non-app pages per slug. (Spec allowed 3–5; 4 is the sweet spot — enough variety, still fits one row on mobile.)
- **Anchor text:** always the app **title** or the target page's H1 phrasing — never "click here", never the raw slug.
- **Reciprocity:** where App A links to App B, App B does *not* have to link back; the graph is directional so the highest-similarity neighbours always win the slot.
- **Non-app-page picks** are chosen from these buckets and matched by theme:
  - Existing routes: `/`, `/apps`, `/planners`, `/moodboard`
  - Proposed blog pages (from `keyword-to-page-map.md`): `/blog/newlywed-game-questions`, `/blog/wedding-trivia-questions`, `/blog/wedding-shoe-game-questions`, `/blog/wedding-guestbook-ideas`, `/blog/wedding-keepsake-ideas`, `/blog/wedding-photo-booth-alternatives`, `/blog/wedding-speeches-ideas`, `/blog/best-man-speech-ideas`, `/blog/wedding-toast-ideas`, `/blog/cocktail-hour-ideas`, `/blog/wedding-reception-ideas`, `/blog/wedding-activities`, `/blog/unique-wedding-ideas`, `/blog/wedding-bingo-cards-printable-vs-live`, `/blog/wedding-after-party`, `/blog/adult-party-games`, `/blog/icebreakers`, `/blog/wedding-lawn-games-alternatives`.

## Notes for implementation

- Related-app rankings live in code as a single map — recommend `data/relatedApps.js` exporting `{ [slug]: string[4] }` consumed by a `<RelatedApps />` component in `components/app-page/`.
- Non-app contextual links are prose links inside `scene` / `objections` / `faq` fields on each app's extended-content object in `data/apps.js`. Add them as markdown-style links so the existing content renderer picks them up (or wrap the fields with a link-injecting renderer).
- If a blog page from the list above hasn't shipped yet, the link should still exist in code but the target route can render a "coming soon" stub — better than deleting and re-adding the link later.
- Once shipped, re-crawl and confirm each app page has exactly 6 non-structural internal links (4 apps + 2 pages) before running paid traffic to any of them.
